## Next native attempt: capture and probe together

Run from the project root on the Pi, with the ESP32 powered and advertising.
Keep other dashboard/standalone scan and connection jobs idle. The dashboard may
stay open to show Bluetooth feedback.

```sh
.venv/bin/python -m tools.capture_ble
```

This starts btmon on controller 0, then runs the equivalent of:

```sh
.venv/bin/python -m bt.client --pair --target-only --read beb5483e-36e1-4688-b7f5-ea07361b26a8 --address 80:B5:4E:E8:B4:69
```

The helper prints its unique `reports/ble-TIMESTAMP-SUFFIX/` directory. It stops
its own btmon process after the attempt. Inspect these files next:

- `capture.btsnoop`: packet trace, replayable with `btmon -r PATH`.
- `btmon.log`: decoded monitor output and any capture permission errors.
- `probe.log`: connection/read progress and client errors.
- `ble-report.json`: fresh report copy, when generated by this attempt.

Capture completion is not service-access success. Confirm actual returned bytes
in the report and inspect ATT/security events before concluding why a read failed.
If btmon exits immediately, inspect its log; the helper will not launch the probe
or change host permissions. This procedure is prepared but has not been run
against hardware from the current container.
